# Frontend Foundations

Подготовлен технический фундамент, а не окончательная дизайн-система.
Источники проверены 21 ноября 2026 года.

## Структура

- `app/` остаётся в корне: маршруты, корневой layout и точка входа глобального CSS.
- `components/ui/` содержит только `Container` и `Button`.
- `styles/tokens.css` содержит CSS-переменные, Tailwind 4 `@theme`, `@theme inline`
  и responsive-переопределения типографики.
- `components/layout/` содержит `Header`. `components/sections/` и `lib/`
  создаются при появлении соответствующих компонентов или утилит.

Сброс стилей обеспечивает уже подключённый Tailwind Preflight. Дополнения размещены
в `@layer base`, компоненты — в `@layer components`, поэтому Tailwind utilities
из `className` могут переопределять базовые правила. Отдельного CSS-фреймворка нет.

## Типографика: подтверждённые значения и временные решения

Получены код, Text Styles и скриншот
[Mobile Typography, 155:1240](https://www.figma.com/design/8EScOSv8Uqhaqgdd7qn5gu/Ptich-Co-Design-System?node-id=155-1240).
Основной шрифт — Manrope через `next/font/google`, включая кириллицу.
Тимофей дополнительно подтвердил **Cormorant Garamond** исключительно для
`Editorial / Quote`; прежнее упоминание экспериментального акцента в
`PROJECT_CONTEXT.md` отражает более раннее состояние решения.
Обе гарнитуры подключены как variable fonts с `subsets: ["latin", "cyrillic"]`
и `display: "swap"`. Основной шрифт body остаётся Manrope. Старые Geist
и Geist Mono из шаблона не загружаются.

| Стиль | Размер / интерлиньяж, px | Вес | Трекинг |
| --- | --- | --- | --- |
| Mobile/H1 | 26 / 32 | 600 | −1% |
| Mobile/H2 | 20 / 28 | 600 | −1% |
| Mobile/H3 | 18 / 26 | 600 | −1% |
| UI/Button | 14 / 20 | 600 | 0 |

Desktop-размеры и интерлиньяж предоставлены Тимофеем 21 ноября 2026 года
по скриншотам Figma. Повторных обращений к Figma MCP не было.
Все значения ниже — `font-size / line-height` в px:

| Класс | Mobile: меньше `lg` | Desktop: от `lg` |
| --- | --- | --- |
| `text-display` | 26 / 32 — временный alias H1 | 68 / 72 |
| `text-heading-1` | 26 / 32 — сохранено | 48 / 56 |
| `text-heading-2` | 20 / 28 — сохранено | 32 / 40 |
| `text-heading-3` | 18 / 26 — сохранено | 18 / 26 — сохранено, Desktop H3 не задан |
| `text-body` | 16 / 24 — временно сохранено | 18 / 28 |
| `text-body-small` | 16 / 24 — временный alias Body | 16 / 24 |
| `text-ui-label` | 14 / 20 — alias существующего UI | 14 / 20 |
| `text-ui-button` | 14 / 20 — alias существующего UI | 14 / 20 |
| `text-ui` | 14 / 20 — сохранено | 14 / 20 |
| `text-caption` | 14 / 20 — временный alias UI Label | 13 / 20 |
| `text-editorial-quote` | 36 / 40 | 60 / 66 |

Значения переведены в `rem` при базовом размере браузера 16px; трекинг — в `em`.
У H1–H3 сохранены вес 600 и трекинг −0.01em, у UI / Button и совместимого
`text-ui` — 600 и 0. Существующий вес Body 400 также сохранён.
Для новых ролей неподтверждённые веса и трекинг не заданы: они наследуются
из контекста (в обычном body — 400 / normal). Alias мобильного Display
заимствует только размер и интерлиньяж H1, а не его вес и трекинг.
Это временное поведение, а не подтверждение параметров Figma.

Токен `--font-accent` ссылается на `--font-cormorant-garamond` из `next/font`
с завершающим `serif` fallback. `text-editorial-quote` объединяет сгенерированные
Tailwind размер/интерлиньяж с `font-family` из одноимённого `@utility`.
Достаточно одного класса, дополнительный `font-accent` не требуется.
В остальных ролях акцентная гарнитура не применяется.

### Responsive и Tailwind 4

Mobile-first: мобильные размеры определены один раз в обычном `@theme`.
В `@layer base` через `@variant lg` переопределяются только CSS-переменные
с подтверждёнными desktop-размерами. Семантические `h1`–`h3`, базовый body
и классы `text-*` используют те же токены; дублирования набора классов нет.

В проекте нет пользовательских breakpoint’ов: используется стандартный
Tailwind `lg` = **64rem / 1024px** при базовых 16px. Он выбран для desktop,
чтобы сохранить компактную типографику на мобильных и планшетных ширинах.
`@variant lg` берёт границу из существующей темы без нового breakpoint’а
и без повторения числового порога в CSS. Граница пока техническая,
её соответствие макетам предстоит подтвердить.

`@theme inline` сохранён для ссылок на гарнитуры и цвета. Размеры вынесены
в обычный `@theme`: иначе Tailwind подставляет мобильный литерал прямо
в utility или `@apply`, и переопределение токена не меняет размер текста.
Теперь сгенерированный CSS содержит `font-size: var(--text-heading-1)`
и ссылки на токены line-height; браузер пересчитывает их при смене viewport.
Механика описана в [документации Tailwind о theme variables](https://tailwindcss.com/docs/theme#referencing-other-variables).

**Неоднозначность Mobile/Body/Regular:** подпись в Figma — 16/24, фактический
Text Style — 16px с line-height 1.2 (19.2px). По текущему поручению Тимофея
сохранено временное 16/24; расхождение остаётся открытым и помечено в CSS.

**Временные значения, не утверждённые токены Figma:**

- Цвета: сохранены нейтральные белый и `#171717` из стартового приложения;
  hover кнопки `#383838`. Фон таблицы типографики не принят за цвет сайта.
- Ширина контейнера: прежние 48rem, включая padding. Горизонтальные поля:
  `clamp(1rem, 4vw, 1.5rem)`; при 320px — по 16px.
- Отступы: 8, 16, 24 и 64px; это временные значения для проверки каркаса.
- Кнопка: минимум 44px по высоте, padding 8/24px, радиус 4px,
  граница 1px, disabled opacity 0.5; focus outline 2px с отступом 3px.
- Mobile Display, Body Small и Caption временно используют размеры существующих
  мобильных ролей: точные значения не предоставлены. Исторические оценки из
  `PROJECT_CONTEXT.md` не использованы как утверждённые токены.

Автоматическая тёмная палитра стартового шаблона убрана: в контексте согласовано
светлое направление, отдельной тёмной темы в реализации пока нет.
Анимаций на этом этапе нет, поэтому отдельные motion/reduced-motion правила не нужны.

## Компоненты

`Container` рендерит обычный `div`, принимает стандартные HTML props, включая
`children`, `className`, `id` и React 19 `ref`. Максимальная ширина включает поля.
Семантические `main`/`section` задаются снаружи; универсального `as` API нет.

```tsx
<main>
  <Container className="py-8">Содержимое страницы</Container>
</main>
```

`Button` имеет одно временное оформление. Без `href` это нативный `button`
с безопасным `type="button"` по умолчанию; поддерживаются `type="submit"`,
`disabled`, обработчики и остальные props кнопки. С `href` это `next/link`,
рендерящий ссылку и поддерживающий навигацию Next.js. TypeScript запрещает
`disabled` и `type` для навигационной формы — у ссылки нет нативного disabled.
Недоступное действие следует представлять настоящей disabled-кнопкой.

```tsx
<Button type="submit">Отправить</Button>
<Button disabled>Действие недоступно</Button>
<Button href="/">На главную</Button>
```

Компоненты не требуют `use client` сами по себе. Для `onClick`, состояния и
будущего открытия виджета импортировать `Button` в клиентский компонент;
обработчик нельзя передавать напрямую из серверной страницы.
Сам компонент `Button` не задаёт URL или поведение бронирования.

### Header

`components/layout/header.tsx` подключён только на главной. Источники:
`docs/design-references/header/Header.png`, `Header Mob.png` и оригинальный
`public/images/brand/logo.svg`. Прозрачный Header остаётся в обычном потоке.
`Container` локально получает `max-w-none`; равные боковые колонки desktop-сетки
центрируют логотип относительно viewport независимо от ширины кнопок.
На существующем `lg` (1024px) появляется логотип и меняется подпись бронирования.

Самостоятельные решения для последующего визуального ревью:

- Экспорт принят за 3× по соотношению размеров: 4176 → 1392px и 864 → 288px.
  Это оценка масштаба, не подтверждённые измерения Figma. Отсюда ориентиры:
  строка 56px, логотип 44px, desktop-кнопка 192 × 56px.
- Сохранены существующие поля Container, вертикальные поля 16px и `text-ui-button`
  14/20. Мобильные действия имеют область не меньше 44px по высоте; у кнопки
  радиус 16px против 12px на desktop. Геометрия локальна для Header.
- Подтверждённый цвет `#A7816A` вынесен в `--header-control-color`, светлый текст
  использует существующий `text-background`. Оригинальный цвет SVG сохранён.
- `Menu` импортируется напрямую из `lucide-react`: size 40px / 56px,
  strokeWidth 2. **Lucide React — основная библиотека иконок проекта**;
  фирменные логотипы остаются оригинальными SVG, общая обёртка для иконок не нужна.
- Меню и бронирование — нативные disabled-кнопки с сохранением полной opacity.
  У них нет фиктивных ссылок или обработчиков. Следующий этап — дизайн и поведение
  раскрывающегося меню, интеграция «Бронируй Онлайн» и размещение поверх Hero.

Проверки Header: `npm run lint`, `npx tsc --noEmit`, `npm run build` прошли.
Проверены production-разметка, CSS и расчёт ширины сетки на 320, 390, 768,
1024 и 1440px: элементы помещаются, desktop-логотип имеет центр 512 / 720px.
Это статическая проверка, не измерение в браузере. Браузерная автоматизация
не запускалась; визуальное ревью выполняет Тимофей.

   Сохранение 16/24 по текущему поручению не закрывает этот вопрос.

   Desktop H3; Body Large пока не реализован — его параметры не предоставлены.

   включая вес, трекинг и начертание Editorial / Quote. Пока подключено normal;
   курсив не выводится из визуальной оценки скриншота.
4. Подтвердить границу переключения типографики: сейчас существующий `lg` (64rem).
5. Цвета по ролям: фон, текст, вторичный текст, границы, действия и состояния.
6. Максимальные ширины, поля и сетку отступов.
7. Варианты кнопок, padding, высоты, радиусы, границы, hover/focus/disabled,
   поведение длинных подписей и при необходимости анимацию.

Для визуальной приёмки финального дизайна ещё нужны макеты целевых компонентов
и проверка в iPhone Safari. Текущие временные значения не являются приёмкой Figma.
